# Bug Fix Batch 21 · Finding 21 · WS 重连后主动 invalidate query · Spec+Plan

**Goal:** `useV5WebSocket` 的 `ws.onopen` 中,若是 **重连**(attemptRef > 0),主动 invalidate `['v5', 'active']` 和 `['v5', 'dashboard']` query cache,避免断线期间数据陈旧。

**Architecture:** 1-line 前 detect reconnect + 2 行 invalidate。无 test(react-query 层行为已被其他 test 覆盖,本 fix 仅是 hook side effect 触发)。

## 问题陈述

`ws.onclose` 只 backoff 重连,不刷新 query cache。断线期间发生的开仓 / 平仓 / 设置变更事件通过 WS 广播,客户端断线时收不到。重连后 `active` / `dashboard` cache 仍是断线前旧快照,直到下次 30s refetch 才刷新,最多 30s 数据陈旧窗口。

## Global Constraints

- Only 1 file: `Rabbit Hunterfronted/hooks/useV5WebSocket.ts`
- 在 `ws.onopen` 内,`attemptRef.current = 0` **之前** capture `wasReconnect = attemptRef.current > 0`
- 若 `wasReconnect` → `qc.invalidateQueries({ queryKey: ['v5', 'active'] })` 和 `qc.invalidateQueries({ queryKey: ['v5', 'dashboard'] })`
- 不改 backoff 逻辑 / heartbeat / watchdog / onmessage / onclose
- 现有 useV5WebSocket 3 tests 无回归
- Single commit,subject EXACT: `fix(useV5WebSocket): 重连成功后主动 invalidate active/dashboard cache (Finding 21)`

```ts
        // Finding 21: 若是重连(attemptRef > 0), 主动刷新可能在断线期间变化的数据
        const wasReconnect = attemptRef.current > 0;
        attemptRef.current = 0;
        lastReceivedRef.current = Date.now();
        setStatus((s) => ({ ...s, connected: true, unhealthyCount: 0 }));
        if (wasReconnect) {
          qc.invalidateQueries({ queryKey: ['v5', 'active'] });
          qc.invalidateQueries({ queryKey: ['v5', 'dashboard'] });
        }
```
